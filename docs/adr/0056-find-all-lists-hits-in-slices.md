# Find All results are a virtual list over Hits

After a background search (ADR 0053) hands hits over, the results window must stay interactive even when Hits holds tens or hundreds of thousands of matches. Describing every hit into an `ObservableCollection` on the UI thread froze the window (a regression from 0.1.1). The results list is now a virtual `IList`: its count tracks `Hits` immediately so the match label and scrollbar extent are correct, and `ReadHitText` runs only when the virtualized ListBox asks for a row (the viewport plus a small cache). Esc cancels the search thread; hits already found stay browsable. Dumping every hit into the collection up front, and capping the list so later hits never appear, were rejected.
