# Find All lists hits in slices so the window stays interactive

After a background search (ADR 0053) hands hits over, the results window describes them on the UI thread: each row reads the hit text and is appended to the bound collections. Describing every hit in one refresh froze the window when a search returned thousands of hits at once, which is a regression from 0.1.1 where the pump interleaved finding and listing. Sync now describes at most a small budget of new rows per tick, caps how many rows the list holds, and keeps the session's full hit count on the group label. Esc cancels the search thread and freezes further listing for that Find All. Find Next still uses the rows already listed and does not wait for the whole list. Dumping every hit into the list on the first refresh, and leaving Esc as clear-mark only, were rejected.
