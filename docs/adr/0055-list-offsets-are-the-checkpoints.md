# The list offsets are the checkpoints, and search jumps through every list the outline holds

A separate index of parser checkpoints every few megabytes was considered and is not built. Every list outside a list entry already keeps each entry's file offset from the scan (ADR 0024, ADR 0052), and the finished outline knows each such list's parent, namespace scope, and count. An entry offset is a place the parser can resume with a known path and entry index: between two siblings of one parent, outside any entity, with nothing else open below that parent. Expanding, revealing, and reading rows deep in a list, nested or not, already open from these offsets in a few milliseconds on the 1 GB files. What still read from the start was a search after the scan whose list was not the root's only list, or whose needle could not be looked for byte by byte.

This amends ADR 0053 and ADR 0054 in three ways:

1. The jump works in every list the finished outline holds outside list entries, at any depth, not only the root's. The conditions per list stay as in ADR 0053: the list is its parent's only child element, the parent has no text, and there is no namespace in scope (XML); JSON jumps in every such array. A parent with several lists, such as a root holding a list under each of its records, jumps in each of them.
2. The needle does not have to be printable ASCII. The search looks for the part of the needle that every hit holds byte for byte. XML splits the needle at spaces, tabs, and line breaks, which attribute values may hold in another form, and at `@` and `#`, which only shown names hold. Ignoring case keeps only ASCII parts. When there are several parts, the one seen least in a sample from the middle of the file is used. When a list has a candidate in nearly every entry, the search stops looking for a while and doubles the pause on each repeat, so a common word costs no more than reading.
3. A hit inside a record that is still open is handed over as soon as no step on its path can still turn into a list entry: each step without an index sits in a record whose outline says that field is not a list. ADR 0053 held every hit until its record closed.

Hits keep the same paths, offsets, lengths, and order as a search that reads every entry. A search started while the scan is running stays on the pump (ADR 0051). Byte-interval checkpoints remain an option for documents whose bulk is not a list, for searches during the scan, and for splitting a full read across threads. They would need the searcher's open text and pending fields at each point, which the list offsets avoid.
